01问题来源

.git/hooks/pre-commit 不是项目本地文件，而是 install-hook.sh 用 ln -sf 建立的符号链接，指向 agate 框架的共享源文件：

$ ls -la .git/hooks/pre-commit
lrwxrwxrwx  .git/hooks/pre-commit -> /home/kity/.agate/scripts/pre-commit-gate.sh

因此这不是 peekview 项目的局部问题——改动会影响机器上所有已安装此 hook 的仓库。

02现象

任务进入 P6 阶段后（P6-acceptance.md 已存在于任务目录），此后任何一次 git commit（无论改动内容是否涉及 P6 证据）都被拦截：

$ git commit -m "..." exit 1
GATE P6-EVIDENCE: 17 条 BDD，证据目录非空
GATE P6-EVIDENCE WARNING: bdd-09-nonadmin-404.png 像素方差 31（<50，疑似纯色/占位图，请确认非充数）
GATE P6-EVIDENCE WARNING: bdd-10-unauth-404.png 像素方差 25（<50，疑似纯色/占位图，请确认非充数）
GATE P6-EVIDENCE WARNING: bdd-01-admin-userlist.png 像素方差 48（<50，疑似纯色/占位图，请确认非充数）
GATE P6-EVIDENCE WARNING: bdd-08-admin-404.png 像素方差 44（<50，疑似纯色/占位图，请确认非充数）

四条全部标注为 WARNING，人工逐张打开核实均为真实渲染内容 （404 页 / 用户列表页），非空白或占位图——方差偏低只是页面本身极简设计（大面积浅色背景 + 小块深色文字）的自然结果。

03问题机理

check-p6-evidence.sh 自身的契约是三态的，设计正确

exit 0全部通过 / exit 1真失败，必须阻断 / exit 2WARNING，仅提醒

exit 1 对应的是三种真实阻断条件——证据目录为空、无 PASS/FAIL 行、截图 md5 完全重复。exit 2 对应的是两种"请人工确认，但不阻断"的场景——像素方差 < 50 疑似占位图、截图 ≤ 1KB。这与 agate 协议里 check-gate.sh 的 P1/P2/P5 分支统一采用的 "exit 2 = 需人工判断，不阻断" 惯例一致。

调用处把两种退出码等同处理

pre-commit-gate.sh:258
bash "$AGATE_ROOT/scripts/check-p6-evidence.sh" "$TASK_DIR" || exit 1

|| 只要左侧命令退出码非 0 就执行 exit 1——exit 1 和 exit 2 被一视同仁地当成阻塞。

同一文件里已有正确的三态处理先例，自相矛盾

主 gate 结果处理逻辑（约第 304 行）本就是三态 case 分支：

pre-commit-gate.sh:304（既有正确写法）
case "$GATE_EXIT" in
    0) echo "GATE $PHASE ($TASK_ID): 通过" >&2 ;;
    1) echo "GATE $PHASE ($TASK_ID): 未通过" >&2; echo "$GATE_OUTPUT" >&2; exit 1 ;;
    2) echo "GATE $PHASE ($TASK_ID): 需主 Agent 手动判断" >&2; echo "$GATE_OUTPUT" >&2 ;;
esac

第 258 行没有沿用同样的写法——大概率是给 check-p6-evidence.sh 新增 exit 2 语义时，忘了同步调用处的处理逻辑。

04影响范围

  • 任何任务只要 P6 截图触发像素方差或小图 WARNING（低对比度/极简设计页面容易触发，非充数场景下也会误伤），P6 及其后所有阶段（P7/P8）的 commit 都会被无差别拦截
  • 影响所有安装此 hook 的仓库——.git/hooks/pre-commit 全部指向同一个符号链接目标，不是 peekview 独有问题

05修改措施（待审核）

把第 258 行的调用方式改为与文件内既有三态 case 模式一致：

状态处理
exit 0无输出，继续
exit 1打印输出，阻断提交（不变）
exit 2打印输出，仅警告，不阻断（新增区分）
拟改为
EVIDENCE_OUTPUT=$(bash "$AGATE_ROOT/scripts/check-p6-evidence.sh" "$TASK_DIR" 2>&1)
EVIDENCE_EXIT=$?
case "$EVIDENCE_EXIT" in
    0) ;;
    1) echo "$EVIDENCE_OUTPUT" >&2; exit 1 ;;   # 真失败：证据缺失/md5重复/无PASS行——照样拦截
    2) echo "$EVIDENCE_OUTPUT" >&2 ;;            # WARNING：低方差/小图——只警告，不阻断
esac

修改范围与风险

  • 改动文件：仅 ~/.agate/scripts/pre-commit-gate.sh（符号链接无需单独改）
  • 是否放宽真失败判定：否。三种真实阻断条件对应的 exit 1 在新逻辑里仍然阻断，不受影响
  • 行为变化：仅 exit 2（像素方差低、截图 ≤ 1KB）从"误阻断"变为"仅打印 WARNING、不阻断"，与脚本自身设计和 P6 phase-card 文档描述（"≤1KB 虽不阻断但会触发 WARNING"）一致
  • 附带修正建议（非必须）：脚本头部第 6 行过期注释 exit 2 = 无 P6 文件 应同步更新为准确描述
  • 影响面：所有使用 ~/.agate 安装此 hook 的项目仓库，行为变得更宽松，不会有项目因此被更严格地拦截

本次 workaround（未修复期间）：T086 任务在 P6/P7 commit 时使用 git commit --no-verify 绕过，经用户明确批准（非默认选择），已在对应 commit message 中注明绕过原因。
