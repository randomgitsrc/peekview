## 复核清单逐项结论

### 1. BDD-2 新阈值 71px（=89px×0.8）的推导是否合理 —— **RESOLVED**

上轮（第 2 轮）打回的核心问题是："40px"这个阈值的来源是一条未经校准的理论公式（padding 32px + 单行行高 18px × 80%），用同一公式反推"改动前"状态得到理论 34px，与 P0-brief 实测基线 17px 相差约 2 倍，且这个已知偏差从未被 analyst 提及或处理——公式本身不可信，套在"改动后"状态上算出的 40px 同样不可信。

本轮的修订方式发生了性质变化，不是"换一个折扣系数"，而是**把阈值来源从理论公式换成了真实测量**：

- 89px 不是公式推算值，是主 Agent 用 Playwright CDP 在 `markdown-test` entry 的移动端页面上，通过 `page.addStyleTag` 实时注入本任务目标 CSS（`padding:16px 16px; overflow-x:visible; flex-wrap:wrap`）后直接测得的真实 `offsetHeight`。测量条件（目标 CSS 内容）与本任务最终要实现的改动完全一致，不存在"测的不是要改的东西"的错配问题。
- 89px 显著高于此前理论公式估算的 40-50px 区间，文本已如实说明原因（`markdown-test` 标签数量较多，`flex-wrap:wrap` 生效后自然换成多行，多行高度自然高于单行理论值）——这是对上轮"公式为何系统性偏低"疑点的合理解释，不是回避。
- 71px = 89px × 0.8 ≈ 71.2，取整 71，四舍五入/取整方式无误。80% 折扣的作用被文本显式限定为"为不同设备/浏览器渲染差异、字体度量误差留出安全边际"——这是在**真实测量值**基础上留安全边际的标准工程做法，与上轮"在一个本身站不住的理论值上打折"性质不同：上轮的问题在于折扣是打在一个未经验证、且已被证明与已知基线不符的数字上；本轮折扣打在一个用与目标实现完全一致的条件实测出的数字上，折扣本身的目的和幅度都有明确、自洽的理由，经得起复核。
- 交叉验证表述准确：71px 相对 17px 基线，"超出逾 3 倍"（71-17=54，54/17≈3.18，超出部分逾 3 倍）与"约 4.2 倍"（71/17≈4.18，总倍数约 4.2 倍）是同一组数字的两种不同表达角度（超出量 vs 总倍数），未见如上轮"拿两个不同测量对象的数字做比较"式的混淆，两个表述本身互相自洽。
- 71px 仍低于实测值 89px，留有边际（89-71=18px），既不会把一个真实改善判 FAIL，也没有把边际留得过大以至于失去区分度（71px 相对 17px 基线仍有约 4.2 倍差距，不会与旧状态混淆）。

结论：71px 的推导链条——真实测量（89px，测量条件与目标实现一致）→ 显式说明的安全边际折扣（80%，理由具体：设备/浏览器/字体渲染差异）→ 取整（71px）——逻辑自洽，且相比上轮的"理论公式打折"在源头可信度上有实质性改善，不是同一个问题换个包装。判定：**通过**。

### 2. 是否明确锚定了具体测试 entry —— **RESOLVED**

- Given 子句明确写为"移动端 viewport 下打开 `markdown-test` entry，分别使用改动前后两版页面"，未使用泛化措辞。
- Then (a) 子句末尾"适用范围说明"段落显式声明："容器高度是内容相关的（标签数量越多、换行行数越多，高度越高），本阈值是专为 `markdown-test` 这一具体测试 entry 标定的下限，不代表对所有 entry 的统一固定期望值"——这句话直接排除了该 71px 数字被误用到标签数量不同、高度天然不同的其他 entry（如 BDD-9 覆盖的另外 9 个 entry）上的风险，与 BDD-9/10/11 的判定标准（相对判据、不依赖绝对像素）划清了界限，不会造成 P6 verifier 误用固定阈值套用到别的 entry 上。
