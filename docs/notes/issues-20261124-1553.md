# Peekview：多文件 Entry 的默认入口与全屏文件定位

## 一、任务目标

完善多文件 Entry 的默认文件选择和全屏阅读定位能力。

本次设计遵循三个原则：

1. `/f` 保持原有设计：用户可以直接在 URL 后追加 `/f`，快速进入全屏阅读模式。
2. 用户不需要手动拼接 `?file=xxx`，也不需要了解 File ID。
3. 全屏模式继续保持纯内容阅读体验，不因为支持指定文件而引入复杂文件导航系统。

本次是一个小范围的体验闭环，不是文件管理系统改造。

## 二、URL 语义

统一以下 URL 行为：

| URL | 行为 |
|---|---|
| `/entry` | 普通模式，打开默认文件 |
| `/entry/f` | 全屏模式，打开默认文件 |
| `/entry?file=123` | 普通模式，打开指定文件 |
| `/entry/f?file=123` | 全屏模式，打开指定文件 |

其中：

- `/f` 只负责阅读模式。
- `file` 只负责指定当前 Entry 中打开的文件。
- 两者相互独立，可以组合使用。
- `file` 使用当前 Entry 下的 File ID，不允许定位其他 Entry 的文件。
- `file` 是程序和深链接使用的 URL 参数，不要求普通用户手动输入。

## 三、默认入口规则

多文件 Entry 未明确指定文件时，按照以下优先级选择：

1. 根目录 `README.md`
2. 根目录 `index.md`
3. 其他文件按照确定性排序选择第一个

约束：

- 文件名匹配建议大小写不敏感。
- 只匹配 Entry 根目录，不递归寻找子目录中的 README。
- 文件列表排序必须稳定，建议按照相对路径排序，必要时使用 File ID 作为最终 tie-breaker。
- 默认入口选择与文件列表排序是两个不同概念，不要通过改变整个文件列表顺序来实现 README 优先。

注意检查并处理现有 `EntryCard.vue`、`EntryListRow.vue` 对 `firstFileId` 的传递，避免它们无条件传入第一份文件，从而绕过默认入口规则。

## 四、全屏入口交互

### 4.1 普通详情页进入全屏

复用现有全屏入口或全屏操作，不要求增加一个专门用于 `/f` 的新按钮。

用户点击全屏入口时：

- 当前选中的是默认文件：进入 `/entry/f`。
- 当前选中的是非默认文件：进入 `/entry/f?file=<当前文件ID>`。

这样用户无需了解 File ID，也不需要手动编辑 URL。

### 4.2 手动追加 `/f`

保留原有快捷方式：

用户直接在普通 Entry URL 后追加 `/f`，仍然进入全屏模式，并展示默认入口文件。

例如：

`/entry` → `/entry/f`

不能要求用户为了进入全屏模式而先经过普通详情页操作。

### 4.3 全屏模式内部

保持现有 `/f` 的纯内容阅读定位：

- 不新增文件树。
- 不新增复杂的文件选择器。
- 不恢复普通详情页 Header、TOC 或其他被全屏模式隐藏的 UI。
- Markdown 正文中的文件链接仍然可以正常切换文件。

本次不要求为全屏模式设计新的文件导航交互。

## 五、文件定位与 URL 状态同步

实现以下行为：

1. 页面初次加载时，读取 `file` 参数。
2. 参数有效且属于当前 Entry：打开指定文件。
3. 参数缺失：使用默认入口规则。
4. 参数无效或不属于当前 Entry：安全回退到默认入口，不允许跨 Entry 读取。
5. 用户在页面内通过文件链接切换文件时，URL 应同步更新。
6. 用户切换回默认文件时，可以移除 `file` 参数，避免 URL 保留不必要的冗余参数。

URL 更新建议使用 `router.replace()`，避免每次文件切换都制造一条浏览器历史记录。

需要特别检查当前页面加载完成后清除 query 参数的逻辑，不能因为原有清理逻辑而意外删除有效的 `file` 参数。

如果 URL 同时存在 `file` 和 `share` 等参数，必须保证各参数各自生效，不得在清理某个临时参数时误删其他有效参数。

## 七、验收标准

### V-01：默认入口

- 含根目录 README.md 的多文件 Entry，打开后默认展示 README。
- 没有 README 但有根目录 index.md，默认展示 index。
- 两者都没有时，回退到稳定排序后的第一个文件。
- 卡片、列表、直接访问 URL 的默认入口行为一致。

### V-02：指定文件直达

- `/entry?file=123` 打开指定文件。
- `/entry/f?file=123` 打开指定文件并进入全屏。
- 无效 File ID 回退默认入口。
- 不能通过修改 file 参数读取其他 Entry 的文件。

### V-03：全屏入口

- 普通详情页当前展示默认文件时，点击全屏进入 `/entry/f`。
- 当前展示非默认文件时，点击全屏进入 `/entry/f?file=<当前文件ID>`。
- 手动在 URL 后追加 `/f` 仍然有效，不要求用户先操作界面。
- 全屏页面保持原有纯内容阅读体验。

### V-04：URL 状态一致性

- 页面加载时，URL 与实际展示文件一致。
- Markdown 内部链接切换文件后，URL 同步变化。
- 切换回默认文件后，可以去掉 `file` 参数。
- `share` 等其他有效 query 参数不被误删。
- 刷新页面后仍然打开 URL 所指定的文件。

### V-05：回归兼容

- 单文件 Entry 行为不变。
- 普通详情页行为不变。
- `/f` 原有快捷访问行为不变。
- Share 链接及其权限验证行为不变。
- 移动端行为正常。
- 文件不存在、Entry 不存在、参数非法等情况有合理回退。

## 八、本次明确不做

- 不新增 `main_file` 数据字段。
- 不新增 Manifest 或文件身份协议。
- 不新增全屏文件树或全屏文件选择器。
- 不要求用户手动输入 File ID。
- 不做跨 Peekview 实例的稳定文件身份保证。
- 不做文件版本管理。
- 不扩展成 Agent 工作目录管理或项目管理功能。
